# NAI Style Lab

NovelAI 작가 태그 조합을 만들고, 둘 중 마음에 드는 쪽을 고르는 것만으로 **내 취향의 그림체**를 찾아 다듬는 앱입니다.
v3.6(브랙퍼스트 원작, 바이트코드 복원본)의 검증된 로직을 그대로 옮기고, 화면과 워크플로를 새로 만들었습니다.

## 실행

`run.bat`을 더블클릭하면 앱 전용 창이 열립니다(pywebview, 화면은 Windows의 WebView2로 그립니다). 창을 닫으면 저장 후 자동으로 종료됩니다.
이미지 생성 중에 창을 닫으면 진행 중인 생성은 기다리지 않고 멈춥니다. 이미 NovelAI에 보낸 한 장의 결과는 받지 못하고 버려지며, 그때까지 만든 것은 저장됩니다. 이미 실행 중이면 새로 띄우지 않고 기존 창을 앞으로 가져옵니다.
앱은 자체 창으로만 동작합니다. 서버를 열지 않으므로(포트 없음) 브라우저나 다른 프로그램, 다른 PC에서는 접근할 수 없습니다.

- 데이터: `data/` (state.json, 실행할 때마다 남기는 직전 백업 state.json.bak, images/, api_key.txt, 썸네일 캐시 thumbs/)
- 오류 기록: `data/app.log`
- 화면은 Windows의 WebView2 런타임으로 그립니다(Windows 11 기본 포함, Windows 10도 업데이트로 설치됨).
- v3.6 폴더와 데이터는 건드리지 않았습니다. v4를 처음 만들 때 v3.6의 `data`를 복사했으므로, 이후 두 앱의 기록은 서로 동기화되지 않습니다.

### 버전과 업데이트

사이드바 위쪽에 지금 버전이 보입니다. 앱은 실행할 때마다 GitHub Releases에 새 버전이 있는지 한 번 확인하고, 있으면 사이드바에 알림이 뜹니다. **설정 → 데이터 → 업데이트**에서 설치하면 새 버전을 받아 앱이 닫혔다가 새 버전으로 다시 열립니다.

- `data/` 폴더는 업데이트할 때 건드리지 않습니다.
- 파일 교체는 앱이 닫힌 뒤 전부 되거나 전혀 안 되거나 둘 중 하나입니다. 중간에 실패하면 이전 파일로 되돌리고 이전 버전으로 다시 엽니다.
- 받은 파일은 크기와 체크섬(GitHub가 알려 주는 SHA-256)을 확인한 뒤에만 설치합니다.
- 데이터 형식이 바뀌는 업데이트라면 새 버전이 처음 실행될 때 원래 파일을 `state.schemaN-날짜.json`으로 남기고 변환합니다. 더 새 버전이 저장한 데이터는 옛 버전이 열지 않습니다.
- 소스 폴더(`_dev`가 있는 폴더)에서는 확인만 하고 설치하지 않습니다.

### 배포 (Python 없는 PC용)

`_dev\make_release.bat`을 실행하면 임베디드 Python 3.14와 Pillow를 함께 담은 `_dev\release\NAI-Style-Lab.zip`이 만들어집니다. 받는 사람은 압축을 풀고 `run.bat`만 실행하면 되며, Python 설치는 필요 없습니다(Windows 10/11 64비트).

새 버전 내기:

1. `app/version.py`의 `VERSION`을 올립니다. 데이터 형식(state.json)이 바뀌면 `app/core.py`의 `SCHEMA`도 올리고 `UPGRADES`에 변환 단계를 추가합니다.
2. `_dev\run_tests.bat` → `_dev\make_release.bat`
3. 커밋·푸시한 뒤 릴리스를 만듭니다. 파일 이름은 반드시 `NAI-Style-Lab.zip`이어야 앱이 찾습니다.

```bat
gh release create v4.0.1 _dev\release\NAI-Style-Lab.zip --title v4.0.1 --notes "바뀐 점"
```

## 워크플로 — 다섯 단계

화면 위쪽의 단계 표시와 **지금 할 일** 버튼이 항상 다음 행동을 알려 줍니다.

| 단계 | 하는 일 | 화면 |
|---|---|---|
| ① 준비 | API 키 입력, 작가 등록, 무작위 조합 만들기 (20개면 충분) | 설정 · 작가 · 조합 만들기 |
| ② 순위 결정 | 새 조합은 10000점에서 시작하지 않고, 기존 순위표 사이에서 **이진 탐색으로 자리**를 찾습니다 (조합 100개 기준 약 7표). 배치 중에는 기존 조합의 Elo가 흔들리지 않습니다. | 대결 |
| ③ 진화 | 지금의 상위 30%(S·A) 조합들의 작가와 가중치를 섞고 바꿔 새 조합(진화 조합)을 만들고, 대결로 상위 30% 사이 어디쯤인지 찾습니다. 그중 가장 낮은 조합에게도 지면 탈락, 이기면 살아남고 그 수만큼 기존 최하위가 제외됩니다. 전체 조합 수는 유지됩니다. | 진화 · 대결 |
| ④ 다듬기 | 고른 그림체의 **작가는 그대로, 가중치만** 바꾼 변형이 챔피언에게 도전합니다. 같은 시드로 그려 그림체 차이만 비교하고, 라운드마다 조정 폭이 ±0.3 → ±0.2 → ±0.1로 줄어듭니다. | 다듬기 · 대결 |
| ⑤ 완성 | 다른 시드 3개로 원본과 챔피언을 나란히 비교하고 확정하면 최종 태그가 복사됩니다. | 다듬기 |

### 대결의 자동 모드

대결 화면은 기본적으로 **자동** 모드입니다. 지금 필요한 대결을 우선순위대로 골라 줍니다.

1. 상위 30% 경계 동점 해소 (어느 모드에서든 가장 먼저, 일반 대결처럼 Elo에 반영)
2. 새 조합 자리 찾기
3. 진화 조합 평가 (만드는 중에는 이미 만들어진 조합의 자리 찾기만, 검증 대결은 다 만든 뒤)
4. 다듬기 챔피언 대결
5. 할 일이 없으면 일반 리그로 순위 결정

`전체 리그`와 `상위 30%` 모드는 순위만 더 다듬고 싶을 때 씁니다.

### 단축키

`←` / `→` 고르기 · `Enter` 비슷함(건너뛰기) · `Backspace` 되돌리기(여러 번 가능) · 휠 확대 · 드래그 이동 (그림체 목록·다듬기·자유 생성에서는 이미지 클릭으로 크게 보기). 원본은 이미지 옆 원본 열기 버튼으로 엽니다.
대결의 확대·이동은 양쪽 그림에 함께 적용되어 같은 부분을 나란히 비교할 수 있습니다. 두 그림이 다 뜨기 전에는 고를 수 없고, 키를 누르고 있어도 한 표만 들어갑니다.
그림체 목록과 작가 표에서는 클릭 선택(다시 클릭하면 해제), `Shift`/`Ctrl` 다중 선택, `Delete` 삭제, `Ctrl+A` 전체 선택, `Esc` 선택 해제.

## 규칙

- **시드 하나로 모든 그림을 그립니다.** 설정의 시드가 비어 있으면 첫 생성 때 무작위로 정해 저장합니다.
- **조합 규칙**(조합당 작가 수, 가중치 범위)은 무작위 조합·진화 조합·다듬기 변형 모두에 적용됩니다. 예전 설정으로 만든 조합에서 가져온 값도 범위 안으로 맞춥니다.
- **진화 조합 만들기**: 상위 30% 조합 하나의 작가 1~3명 교체·삭제·추가(가중치 ±0.3), 상위 30% 조합 둘 섞기, 완전 무작위를 1/3씩. 부모는 순위가 높을수록 잘 뽑힙니다(1위가 꼴찌의 2배). 새로 뽑는 작가는 지금 상위 30%에 적게 쓰인 작가일수록, 그리고 작가 점수가 높을수록 잘 뽑힙니다(최고 점수 작가가 평균의 2배, 최저는 0.5배, 기록이 없는 작가는 평균). 진화 기록에 방식과 부모를 남깁니다.
- **투표가 모순될 때**(윗 순위는 이기고 아랫 순위에는 짐) 어긋나는 표가 가장 적은 자리로 배치하고, 합격선 근처는 검증 대결을 더 합니다.
- **탐색 종료 신호**: 2세대 연속으로 살아남은 진화 조합이 없으면 다듬기로 넘어가라고 안내합니다.
- **최종 확인**에서 챔피언이 원본 그대로면 원본만 다른 시드로 한 번씩 그립니다. 중간에 멈추면 라운드 결과 화면으로 돌아갑니다.
- **점수 단위**: Elo는 보통의 10배 단위(시작 10000점, K 320)로 정수만 씁니다. 1000점 단위에서 반올림 때문에 생기던 동점을 줄입니다. 예전 데이터는 처음 실행할 때 한 번 10배로 바뀝니다.
- **작가 점수**: 작가 표의 점수는 그 작가가 들어간 평가된 조합들의 Elo에서 작가의 몫을 떼어 낸 값입니다(평균 0, 가중치 1 기준). 함께 쓰인 작가의 영향과 가중치를 구분하고, 들어간 조합이 적으면 0에 가깝게 나옵니다.
- 대결에서 고르면 두 조합의 Elo가 어떻게 바뀌었는지 1초 동안 보여 준 뒤 다음 대결로 넘어갑니다(비슷함 등으로 그대로면 +0, 평가중인 조합은 평가중).
  **블라인드** 토글을 켜면 티어·Elo·전적·태그를 ???로 가리고 그림만 보고 고르며, 고른 뒤 그 1초 동안 모두 공개합니다.
- 탈락·제외된 조합은 지우지 않고 그림체 목록에 탈락 · 제외 표시로 남습니다. 부활, Elo 수정, 삭제, 전부 삭제가 가능합니다. 진화 평가·자리 찾기 중인 조합의 Elo를 고치면 그 순위표에도 바로 반영됩니다.

## 안전장치

- 저장은 임시 파일에 쓰고 디스크에 확실히 기록한 뒤 통째로 교체합니다. 백신이 파일을 잠시 잡아도 짧게 재시도합니다. 실행할 때마다 직전 상태를 `state.json.bak`으로 남깁니다.
- state.json을 읽을 수 없으면 덮어쓰지 않고 `state.corrupt-날짜.json`으로 보존한 뒤 알립니다.
- NovelAI 429·5xx는 5/15/45초 뒤 재시도, 401·403(키 오류)은 즉시 작업을 멈춥니다. 그 밖의 오류로 3장이 연속 실패해도 작업을 멈춥니다.
- 설정에서 범위를 벗어난 값은 저장하지 않고 이전 값으로 되돌립니다.
- 데이터 불러오기는 zip을 모두 풀고 내용을 확인한 뒤에야 지금 데이터를 바꿉니다. 실패하면 지금 데이터는 그대로입니다.
- 데이터 내보내기 zip에는 API 키도 들어갑니다(다른 PC에서 불러오면 바로 쓸 수 있게). zip을 남에게 줄 때는 조심하세요. 키가 없는 예전 zip을 불러오면 지금 키를 그대로 씁니다.
- 웹 서버가 없습니다. 화면과 그림은 창 안에서 디스크의 파일로 바로 그려지고(web/, images/, thumbs/ 안의 파일만), 화면의 요청은 pywebview 채널로 Python에 직접 전달됩니다. 창 밖 주소로 가는 링크는 창 안에서 열리지 않고 기본 브라우저로 열립니다.
- 중복 실행 확인은 실행마다 바뀌는 키가 있어야 쓸 수 있는 이름 있는 파이프로 합니다(네트워크 아님). 서버를 쓰던 이전 버전이 같은 data 폴더로 실행 중이면 새 버전은 시작하지 않고 그 창을 먼저 닫으라고 알립니다.

## 구조

```
main.py          앱 창(pywebview) 열기, 창 안 파일 제공, 중복 실행 시 기존 창 앞으로, 창을 닫으면 저장 후 종료
app/core.py      NovelAI API, 스타일 문자열, Elo·티어, 진화 조합 만들기, 순위표 배치, 데이터 형식 (순수 로직)
app/engine.py    상태·워크플로·생성 작업 (모든 변경은 잠금 하나로)
app/bridge.py    화면 ↔ 엔진 연결(요청 처리), 창에 보여 줄 파일 고르기, 썸네일
app/updater.py   업데이트 확인·다운로드, 앱이 닫힌 뒤 파일 교체(별도 프로세스)
app/version.py   지금 버전과 릴리스 저장소
web/             화면 (index.html, app.css, js/)
python/          임베디드 Python (저장소에는 없음, _dev\setup_python.bat이 만듦)
_dev/            개발용: 오프라인 테스트(tests/), 배포 zip 만들기, Python 설치, requirements.txt
```

## 테스트

```bat
_dev\run_tests.bat
```

테스트는 가짜 생성기를 쓰므로 NovelAI를 호출하지 않습니다.

- `test_core.py`: 진화 조합 범위, 가중치 변형, 새 조합 배치(100개 순위표에서 7표 이내 정확한 자리), 진화 평가, 동점, 저장
- `test_engine.py`: 빈 폴더에서 시작해 조합 생성 → 배치 → 되돌리기 → 진화·확정 → 경계 동점 → 다듬기·최종 확인 → 재시작 후 복원 → 부활·삭제까지 전체 흐름
- `test_bridge.py`: 요청 왕복, 창에 보여 줄 파일(경로 탐색 차단), 썸네일, 불러오기·내보내기, 드래그, 창을 닫을 때 입력 중이던 설정 저장
- `test_updater.py`: 버전 비교, 업데이트 확인, 다운로드 검사(크기·체크섬·내용), 전부 아니면 전무인 교체(data 그대로, 실패 시 되돌림), 데이터 형식 변환
- `test_lifecycle.py`: 포트를 열지 않음, 중복 실행 시 기존 창 앞으로, 새 코드로 교체, 창을 닫으면 저장 후 종료, 이전 버전 실행 중 처리 (실제 창 대신 가짜 창 사용)

## 소스에서 실행

앱은 `python\` 폴더의 임베디드 Python으로 실행됩니다. 이 폴더는 저장소에 없으므로 처음 한 번 `_dev\setup_python.bat`으로 만듭니다([uv](https://docs.astral.sh/uv/) 필요). `_dev\requirements.txt`를 바꾼 뒤에도 다시 실행합니다.

```bat
_dev\setup_python.bat
run.bat
```
